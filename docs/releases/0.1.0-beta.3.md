# Batuta v0.1.0-beta.3

`v0.1.0-beta.3` is a maintenance release of Batuta from
`franciscpd/batuta-compozy`.

## Install

```bash
compozy extension install github:franciscpd/batuta-compozy --allow-unverified --yes
compozy extension enable batuta
```

Pin this version with `github:franciscpd/batuta-compozy@v0.1.0-beta.3`.
Update an existing installation with
`compozy extension update batuta --allow-unverified --yes`; remove it with
`compozy extension remove batuta --global`. The release carries exactly two
assets, `batuta-v0.1.0-beta.3.tar.gz` and
`batuta-v0.1.0-beta.3.tar.gz.sha256`. The daemon verifies the archive against
the sidecar. Manual verification: [docs/verify.md](https://github.com/franciscpd/batuta-compozy/blob/v0.1.0-beta.3/docs/verify.md).

## Maintenance changes

- The operational CompozyOS guard now evaluates the semantic-version floor
  directly. Release builds at `v0.3.0-beta.14` or later are accepted without a
  per-commit allowlist, while custom post-tag builds remain visible through a
  warning.
- Local republication now stages the five extension files in a guarded
  temporary staging directory, validates that exact tree, then reinstalls and
  enables it. The superseded content-addressed package store and per-user lock
  helper were removed.
- Guard and contract failures now include the observed version or command
  output needed to diagnose an unrecognized local CompozyOS build.
- Internal design specifications and implementation plans now live under
  `docs/internal/`, separate from the public extension package and guides.

The autonomous QA cycle discussed in
[issue #1](https://github.com/franciscpd/batuta-compozy/issues/1) is not part of
this release.

## Verified scope

The package still contains one `batuta` agent, one `batuta-routing` skill, and
one `batuta-deliver` Loop. Batuta remains resource-only orchestration: it
classifies, decomposes, dispatches, and reports, and does not write
implementation code. The manifest floor remains `v0.3.0-beta.13`; the local
operational guard requires `v0.3.0-beta.14` or later.

## Known upstream limitations

These CompozyOS limitations are unchanged: executor sessions are not visually
nested and remain active/idle after normal terminal completion.
