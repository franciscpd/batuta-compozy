# Batuta v0.1.0-beta.6 (candidato)

[Versão em inglês](0.1.0-beta.6.md)

`v0.1.0-beta.6` é o próximo candidato do Batuta após as únicas releases remotas
publicadas, `v0.1.0-beta.2` e `v0.1.0-beta.3`. Ainda não é uma tag nem uma
release do GitHub. O Batuta continua sendo um projeto independente da
comunidade em `franciscpd/batuta-compozy`.

O candidato é uma extensão Go que usa diretamente o SDK Go oficial do Compozy
`v0.3.0-beta.21`. O commit de fonte do Compozy
`382976d4b43274630a4b67445812fd4a0216dbcc` foi testado somente para build e
lint: seu binário beta.20 não concluiu a qualificação de Start em runtime. O uso
em runtime permanece bloqueado até um binário Compozy beta.21 ou posterior.

## Instalação após a release

```bash
compozy extension install github:franciscpd/batuta-compozy --allow-unverified --yes
compozy extension enable batuta
```

Depois que a tag existir, fixe-a com
`github:franciscpd/batuta-compozy@v0.1.0-beta.6`. Atualize com
`compozy extension update batuta --allow-unverified --yes`; remova com
`compozy extension remove batuta --global`. Consulte
[docs/verify.pt-BR.md](../verify.pt-BR.md) para proveniência, validação e staging
do candidato.

## O que muda

- O pacote inventaria um agente `batuta`, a skill `batuta-routing`,
  `batuta-deliver`, `batuta-task` e nove tools hospedadas do Batuta, incluindo
  `ext__batuta__delivery_graph`.
- Cards de esclarecimento do SDD resolvem a intenção do produto antes da
  aprovação das tasks. Uma task em execução usa `ask` tipado somente para uma
  decisão material da entrega; a resposta retoma o mesmo filho e worktree.
- Inventário automático de executores e uma geração imutável de domínio ×
  complexidade admitem ondas dependency-safe com no máximo quatro worktrees
  isolados de task.
- Commits verificados de task são integrados de forma determinística em um
  worktree canônico de integração. Um conflito de prefixo recebe reexecução
  canônica com execução imutável e base novas.
- Uma única revisão final executa após a integração. A publicação envia e
  verifica automaticamente o HEAD revisado exato e abre ou reutiliza um PR; o
  merge continua manual.
- Capacidade, limites de task/pai novo, orçamentos, pausas,
  cancelamento/stall, fallback esgotado e evidência ambígua interrompem com
  segurança. Um worktree de diagnóstico retido é evidência terminal bloqueada,
  não cleanup bem-sucedido.

## Validação do candidato

Execute as verificações locais do candidato a partir de um diretório temporário
de staging e de um `COMPOZY_HOME` isolado. A geração em staging contém fontes
Go e somente os recursos declarados da extensão; ela exclui planos, specs, QA e
artefatos de SDD. Seu inventário deve expor exatamente os dois Loops e todas as
nove tools hospedadas.

O Compozy atual exibe as sessões dos executores na hierarquia pai/filho e
encerra as sessões run-agent após o assentamento terminal. Fixtures
determinísticas comprovam os limites da extensão e do Git do Batuta; elas não
alegam resultado vivo de provider externo ou forge.
