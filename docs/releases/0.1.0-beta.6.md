# Batuta v0.1.0-beta.6 (candidate)

`v0.1.0-beta.6` is the next Batuta candidate after the only published remote
releases, `v0.1.0-beta.2` and `v0.1.0-beta.3`. It is not a tag or GitHub release
yet. Batuta remains an independent community project from
`franciscpd/batuta-compozy`.

The candidate is a Go extension using the official Compozy Go SDK
`v0.3.0-beta.21` directly. Its tested development compatibility baseline is
Compozy source commit `382976d4b43274630a4b67445812fd4a0216dbcc`; that is not a
claim that every public Compozy binary has released this graph action surface.

## Install after release

```bash
compozy extension install github:franciscpd/batuta-compozy --allow-unverified --yes
compozy extension enable batuta
```

After the tag exists, pin it with
`github:franciscpd/batuta-compozy@v0.1.0-beta.6`. Update with
`compozy extension update batuta --allow-unverified --yes`; remove with
`compozy extension remove batuta --global`. See [docs/verify.md](../verify.md)
for provenance, validation, and candidate staging.

## What changes

- The package inventories one `batuta` agent, the `batuta-routing` skill,
  `batuta-deliver`, `batuta-task`, and nine hosted Batuta tools including
  `ext__batuta__delivery_graph`.
- SDD clarification cards settle product intent before tasks are approved. A
  running task uses typed `ask` only for a material delivery decision; its
  answer resumes the same child run and task worktree.
- An automatic executor inventory and immutable domain × complexity generation
  admit dependency-safe waves with at most four isolated task worktrees.
- Verified task commits integrate deterministically into one canonical
  integration worktree. A prefix conflict receives canonical conflict
  reexecution with a new immutable execution and base.
- One final review runs after integration. Publication automatically pushes and
  verifies the exact reviewed HEAD and opens or reuses one PR; merge remains
  manual.
- Capacity, task/fresh-parent caps, budgets, pauses, cancellation/stall,
  fallback exhaustion, and ambiguous evidence stop safely. A retained diagnostic
  worktree is terminal blocked evidence, not successful cleanup.

## Candidate validation

Run local candidate checks from a temporary staging directory and an isolated
`COMPOZY_HOME`. The staged generation contains Go sources and only declared
extension resources; it excludes plans, specs, QA, and SDD artifacts. Its
inventory must expose exactly the two Loops and all nine hosted tools.

executor sessions are not visually nested and remain active/idle after normal
terminal completion. Deterministic fixtures prove Batuta's extension and Git
boundaries; they do not claim a live external provider or forge result.
