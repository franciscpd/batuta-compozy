# Batuta v0.1.0-beta.5 (candidate)

`v0.1.0-beta.5` turns Batuta into a code-backed Compozy extension that owns
automatic inventory, domain routing, bounded recovery, and verified
publication. It is an independent community project from
`batuta-ai/compozy`.

The release remains a candidate. It uses the official Compozy Go SDK
`v0.3.0-beta.21` with no replacement or pseudo-version, but public promotion
still requires an official Compozy binary containing child `run-loop`
`config_overrides`. Local evidence uses an isolated compatible preview.

## Install after release

```bash
compozy extension install github:batuta-ai/compozy --allow-unverified --yes
compozy extension enable batuta
```

Pin it with `github:batuta-ai/compozy@v0.1.0-beta.5`. Update with
`compozy extension update batuta --allow-unverified --yes`; remove with
`compozy extension remove batuta --global`. Integrity and provenance steps
are documented in [docs/verify.md](../verify.md).

## Breaking beta changes

- `auto_commit` is no longer an operator preference. Implementation and review
  receive literal `auto_commit=true`.
- Healthy publication no longer waits on a human gate. Batuta plans, pushes,
  opens one PR per delivery phase, and verifies the exact HEAD automatically;
  merge remains manual.
- Runtime selection is no longer one global complexity map. Every task carries
  a canonical domain in `type` plus `complexity`, and Batuta owns the exact
  populated matrix cells.
- The standalone resource-only package is replaced by a Linux/amd64 code-backed
  extension generation with eight hosted tools.

## New behavior

- Redacted inventory of Compozy, Codex, OpenCode, and Cursor Agent.
- Deterministic exact-model selection from the live Compozy catalog. Frontend
  can prefer Cursor Agent/Grok 4.6 when the exact ACP ID is available.
- Migration-free matrix archival that never mutates stored Compozy Loop config.
- One stable Batuta `delivery_id` with immutable routing/task/worktree evidence
  and a new Compozy `run_id` for each attempt.
- Fresh-run fallback for only incomplete tasks; exact failed tasks advance to
  the next candidate. Attempt cap 4, token ceiling, drift checks, and the
  original 14,400-second deadline stop the loop deterministically.
- Replay-safe start/recovery with single-run adoption after a lost response and
  fail-closed ambiguity when multiple matching runs exist.
- Automatic publication with fresh worktree status, exact local/upstream HEAD
  checks, durable operation IDs, a real PR URL, and independent verification.

## Verified local scope

Deterministic local automation proves inventory contracts, backend/low routing
to Codex, frontend/medium routing to Cursor/Grok 4.6, two fresh attempts in one
worktree, carry-forward commits, remote bare push, and exact upstream HEAD
verification. The local PR URL is simulated; a disposable real-provider and
real-forge PR smoke remains `blocked-verify` release acceptance work.

The extension is Linux/amd64-only until Compozy supports platform-aware
extension assets. Executor sessions are not visually nested and may remain
active/idle after normal terminal completion.
