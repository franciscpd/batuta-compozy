# Batuta v0.1.0-beta.3

[Versão em inglês](0.1.0-beta.3.md)

`v0.1.0-beta.3` é uma release de manutenção do Batuta em
`franciscpd/batuta-compozy`.

## Instalação

```bash
compozy extension install github:franciscpd/batuta-compozy --allow-unverified --yes
compozy extension enable batuta
```

Fixe esta versão com `github:franciscpd/batuta-compozy@v0.1.0-beta.3`.
Atualize uma instalação existente com
`compozy extension update batuta --allow-unverified --yes`; remova com
`compozy extension remove batuta --global`. A release contém exatamente dois
assets, `batuta-v0.1.0-beta.3.tar.gz` e
`batuta-v0.1.0-beta.3.tar.gz.sha256`. O daemon verifica o archive pelo sidecar.
Verificação manual: [docs/verify.md](https://github.com/franciscpd/batuta-compozy/blob/v0.1.0-beta.3/docs/verify.md).

## Mudanças de manutenção

- O guard operacional do CompozyOS passou a avaliar diretamente o piso de
  versão semântica. Builds de release em `v0.3.0-beta.14` ou posteriores são
  aceitas sem allowlist por commit, enquanto builds customizadas posteriores à
  tag continuam visíveis por um aviso.
- A republicação local passou a preparar os cinco arquivos da extensão em um
  diretório temporário protegido, validar exatamente essa árvore e então
  reinstalar e habilitar. O antigo store de pacote content-addressed e o helper
  de lock por usuário foram removidos.
- Falhas de guard e contrato passaram a incluir a versão ou saída do comando
  observada, necessárias para diagnosticar uma build local não reconhecida do
  CompozyOS.
- Specs internas de design e planos de implementação passaram a ficar em
  `docs/internal/`, separados do pacote público da extensão e dos guias.

O ciclo autônomo de QA discutido na
[issue #1](https://github.com/franciscpd/batuta-compozy/issues/1) não faz parte
desta release.

## Escopo verificado

O pacote ainda contém um agente `batuta`, uma skill `batuta-routing` e um Loop
`batuta-deliver`. O Batuta continua sendo orquestração resource-only: classifica,
decompõe, despacha e reporta, sem escrever código de implementação. O piso do
manifest continua sendo `v0.3.0-beta.13`; o guard operacional local exige
`v0.3.0-beta.14` ou posterior.

## Limitações upstream conhecidas naquela versão

Na época da beta.3, as sessões dos executores não eram visualmente aninhadas e
permaneciam `active/idle` após a conclusão terminal normal. O Compozy atual já
resolveu esses dois comportamentos; esta seção preserva o registro histórico da
release.
